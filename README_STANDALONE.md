# Razy Fund — standalone backend

The wallet and admin API no longer import or call Supabase. There is no SQL schema to apply and no external database dependency in these routes.

## Required server environment

- `WALLET_SECRET`: random secret, at least 32 characters.
- `ADMIN_SESSION_SECRET`: separate random secret, at least 32 characters.
- `ADMIN_PASSWORD_HASH`: PBKDF2 hash generated by `scripts/hash-admin-password.mjs`.

## Storage limitation

This implementation stores accounts, balances, votes, events, and audit entries in process memory. It is standalone and works while the server process remains alive, but data is lost when a server process restarts or a serverless worker is replaced. Multiple worker instances do not share state. Durable cross-instance persistence requires some persistent storage service; this project intentionally does not configure one.

## Security behavior

- Wallet identity is held in an HMAC-signed, HttpOnly cookie.
- Balances and votes are held server-side, not accepted from browser-submitted balances.
- The browser cannot grant itself tokens.
- Admin login uses a PBKDF2 password hash and an HMAC-signed, HttpOnly session cookie.
- Login attempts are rate-limited per server process.
- Simulated checkout never awards tokens.
